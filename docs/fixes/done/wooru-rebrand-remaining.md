## 3. Deliberately not changed — do not "fix" these

Each was considered and rejected for a reason. Changing them costs work and gains nothing.

| Thing | Why it stays |
|---|---|
| **Google Cloud project ID** `societyservicehub` | **Permanent** — Google does not allow renaming. Changing it means a new project: rebuilt consent screen, new client IDs, re-pasting credentials into Supabase, and a window with sign-in broken. The ID is never shown to end users. Only the *display name* and the consent-screen *App name* are user-visible, and both are already `Wooru`. |
| **Supabase org + project names** | Dashboard labels only. What a browser sees is the project **ref** (`mbzvcaoulawdugfearmj`), a random string that never carried the brand. Renaming does not change the ref. *(Mild counter-argument: once preprod exists, `wooru-preprod` sitting next to `societyservicehub@gmail.com's Project` is exactly the confusion that sends a migration to the wrong environment. Cheap to rename then.)* |
| **Vercel personal username** `societyservicehub-6292` | A deployment URL is `<project>-<hash>-<team-slug>`. The slug is the **team**, already `wooru`. No project lives under the personal account, so this appears nowhere. |
| **Old deployment URLs** `commloom-*-society-service-hub.vercel.app` | Vercel deployment URLs are immutable per deployment — they permanently record the names in force at build time. Unlinked and unguessable without the hash. `vercel remove commloom --safe` prunes them if desired. |
| **Applied migrations containing `societyservicehub@gmail.com`** | `supabase db push` tracks migrations by **filename, not content** — editing an applied file is a silent no-op. `20260901000000` supersedes them via `CREATE OR REPLACE`. The old files are history and must stay. |
| **Old Cloudinary URLs under `society_hub/`** | 3 listing images. `secure_url` values are absolute and already persisted in the database, so they resolve forever. There is nothing to migrate. |
| **`docs/archive/`** | Explicitly historical per [`../README.md`](../README.md). Rewriting it destroys the record of what things were called when. |
| **`societyservicehub@gmail.com` as a platform admin** | Retained on purpose. It holds admin through its profile row (`app_role='admin'`, `community_id IS NULL`), independent of the hardcoded break-glass address. Two admins mean each is the other's recovery path. |

## 4. Adjacent risks surfaced during the rebrand

Not rebrand work, but found while doing it and worth not losing.

### 4.1 No type-check gate before production 🔴

`main` is Vercel's production branch and commits now go **directly to `main`** — no feature branches, no PR checks. Nothing between the editor and `wooru.in` runs `npx tsc --noEmit`, which is the repo's only validation gate.

This already bit: commit `245f3e2` shipped `<Rupees size={15} />`, and since `SIZES` is keyed `sm|md|lg`, `SIZES[15]` was `undefined` and the next line read `s.integer` — **crashing the provider detail screen for any provider with a numeric field** (salary, charges). Fixed in `35f4454`.

A pre-commit hook or a GitHub Action on `main` running `npx tsc --noEmit` would have caught it. ~10 lines either way.

### 4.2 Vercel Preview scope points at production Supabase

Set deliberately, because preprod does not exist and the alternative was preview builds that fail. **Repoint the moment preprod exists** — it is the core safety property of [`../new_features_to_implement/two-environment-setup-plan.md`](../new_features_to_implement/two-environment-setup-plan.md).

### 4.3 SMTP is a latent dependency

Auth emails go through Supabase's built-in service, which is rate-limited and documented as development-only. **Currently harmless**: Google-only onboarding sends no confirmation emails, and the reset flow is hidden.

It becomes a live problem the moment `EMAIL_AUTH_UI_ENABLED` is flipped to `true` — an unsent confirmation is a user who cannot sign in and is told nothing. See [`../disabled-features.md`](../disabled-features.md) §1.

### 4.4 The landing page is unreachable at `/`

[`../../vercel.json`](../../vercel.json) rewrites `/` → `/landing.html`, but the rewrite **never fires**: Vercel matches the filesystem first, and `dist/index.html` exists. So `wooru.in/` serves the app, and the marketing page — rebranded as part of this work — is only reachable at `/landing.html`.

Pre-existing and unrelated to the rebrand, but it means the rebranded landing page is currently seen by nobody.

### 4.5 Supabase auth email templates

Confirmation, reset and magic-link templates live in the dashboard, not in git, so no code sweep can see them. **They were never checked** and may still carry the old brand. Inert while Google-only onboarding is in force, but they are the first thing to review if email auth returns.
